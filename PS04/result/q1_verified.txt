4. Evidence : where does each 'y' actually live?
====================================================================

----- 4.1 ELF type of the four binaries -----
$ file q1_static q1_auto q1_static_nopie q1_auto_nopie
q1_static:       ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2
q1_auto:         ELF 64-bit LSB pie executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2
q1_static_nopie: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2
q1_auto_nopie:   ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked, interpreter /lib64/ld-linux-x86-64.so.2

----- 4.2 symbol table : the static y has a name and an address, the auto y does not -----
$ nm q1_static_nopie | grep -i ' y'          # 'D' = initialised data section
0000000000404018 d y.0
$ nm q1_static       | grep -i ' y'          # PIE: same symbol, address = file offset
0000000000004010 d y.0
$ nm q1_auto_nopie   | grep -i ' y'          # nothing: the auto y is a stack slot
(exit status = 1   -> 1 means grep found no symbol named y)

----- 4.3 the .data section that holds the static y -----
$ readelf -S q1_static_nopie | grep -A1 ' .data '
  [25] .data             PROGBITS         0000000000404008  00003008
       0000000000000014  0000000000000000  WA       0     0     8

$ readelf -h q1_static_nopie | grep -E 'Type|Entry'
  Type:                              EXEC (Executable file)
  Entry point address:               0x401050
$ readelf -h q1_static       | grep -E 'Type|Entry'
  Type:                              DYN (Position-Independent Executable file)
  Entry point address:               0x1060

----- 4.4 same PIE binaries run with ASLR switched off (setarch -R) -----
$ setarch -R ./q1_static | grep address        # run 1, 2, 3
The address of y is 0x555555558010
The address of y is 0x555555558010
The address of y is 0x555555558010

$ setarch -R ./q1_auto   | grep address        # run 1, 2, 3
The address of y is 0x7fffffffe290
The address of y is 0x7fffffffe290
The address of y is 0x7fffffffe290

----- 4.5 PIE: printed address = (random load base) + (fixed offset from the symbol table) -----
offset of y inside the file (from nm) = 0x0000000000004010
$ ./q1_static | head -2        # run 1, 2, 3   ->  base = printed address - offset
printed &y = 0x59dfb0606010    load base = 0x59dfb0602000
printed &y = 0x6234ef9d2010    load base = 0x6234ef9ce000
printed &y = 0x64fd3cae1010    load base = 0x64fd3cadd000

link-time address of y in the no-pie binary (from nm) = 0x0000000000404018
$ ./q1_static_nopie | head -2  # run 1, 2, 3   ->  base = 0, address is the link-time one
printed &y = 0x404018    load base = 0x0
printed &y = 0x404018    load base = 0x0
printed &y = 0x404018    load base = 0x0

----- 4.6 the address printed by the auto version is really a stack address -----
(ASLR switched off with setarch -R so that the numbers can be compared directly)
$ setarch -R ./q1_auto | grep address | head -1
The address of y is 0x7fffffffe290
$ setarch -R bash -c 'grep \[stack\] /proc/self/maps'
7ffffffde000-7ffffffff000 rw-p 00000000 00:00 0                          [stack]
$ setarch -R ./q1_static | grep address | head -1     # for comparison: not on the stack
The address of y is 0x555555558010
