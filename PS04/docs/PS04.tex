\section{ข้อ 1: Static Storage Class}
% =====================================================================

\subsection{หลักการพื้นฐานของ Storage Class}

Storage Class ในภาษา C กำหนดคุณสมบัติสำคัญ 3 ประการของตัวแปร ได้แก่
\begin{itemize}[leftmargin=*]
  \item \textbf{ขอบเขต (Scope):} บริเวณในโปรแกรมที่สามารถเข้าถึงชื่อตัวแปรนั้นได้
  \item \textbf{อายุการใช้งาน (Lifetime):} ช่วงเวลาที่ตัวแปรคงอยู่ในหน่วยความจำระหว่างการทำงาน
  \item \textbf{ตำแหน่งในหน่วยความจำ (Memory Segment):} บริเวณที่ระบบจัดสรรพื้นที่ให้ เช่น Stack หรือ Data Segment
\end{itemize}

% ---------------------------------------------------------------------
\subsection{Step 1: โค้ดโปรแกรมที่มี \code{static} (คอมไพล์แบบปกติ)}
% ---------------------------------------------------------------------

\begin{lstlisting}[style=cstyle,caption={\code{src/q1\_static.c} โค้ดเริ่มต้นตามใบงาน}]
#include <stdio.h>
#include <stdlib.h>

void main()
{
    auto int x = 3;

    while (x > 0)
    {
        static int y = 5;
        y++;

        printf("The value of y is %d\n", y);
        printf("The address of y is %p\n\n", &y);

        x--;
    }
}
\end{lstlisting}

\subsubsection{ผลการทดลอง}

ผลการคอมไพล์และรันโปรแกรม 3 ครั้ง:

\begin{lstlisting}[style=terminal,caption={ผลการทดลอง Step 1 (รัน 3 ครั้ง)}]
$ gcc -Wall -Wextra -o q1_static q1_static.c

q1_static.c:10:6: warning: return type of 'main' is not 'int' [-Wmain]

$ ./q1_static                              # Run 1
The value of y is 6      The address of y is 0x5c5469622010
The value of y is 7      The address of y is 0x5c5469622010
The value of y is 8      The address of y is 0x5c5469622010

$ ./q1_static                              # Run 2
The value of y is 6      The address of y is 0x60a5f69ee010
The value of y is 7      The address of y is 0x60a5f69ee010
The value of y is 8      The address of y is 0x60a5f69ee010

$ ./q1_static                              # Run 3
The value of y is 6      The address of y is 0x5faa56b46010
The value of y is 7      The address of y is 0x5faa56b46010
The value of y is 8      The address of y is 0x5faa56b46010
\end{lstlisting}

\subsubsection{การวิเคราะห์ผลการทดลอง}

\begin{itemize}[leftmargin=*]
  \item \textbf{ค่าของตัวแปร ($y = 6 \to 7 \to 8$):} ตัวแปร \code{static} ถูกจัดสรรไว้ใน Data Segment (\code{.data}) และได้รับการกำหนดค่าเริ่มต้น ($5$) เพียงครั้งเดียวตั้งแต่ขั้นตอนคอมไพล์และโหลดโปรแกรม เมื่อวนลูปคำสั่งประกาศจะไม่ถูกทำงานซ้ำ คำสั่ง \code{y++} จึงบวกค่าสะสมต่อเนื่องจากรอบก่อนหน้า
  \item \textbf{ที่อยู่ของตัวแปรภายในการรันเดียวกัน:} มีตำแหน่งคงที่เดิมทั้ง 3 รอบของการวนลูป เนื่องจากระบบใช้พื้นที่ใน Data Segment ตำแหน่งเดิมตลอดอายุของโปรแกรม
  \item \textbf{ที่อยู่ของตัวแปรข้ามการรัน:} มีการเปลี่ยนแปลงทุกครั้งที่สั่งรันใหม่ เนื่องจาก Ubuntu ตั้งค่าให้ \code{gcc} สร้างไบนารีแบบ PIE (Position-Independent Executable) เป็นค่าเริ่มต้น ทำงานร่วมกับกลไก ASLR (Address Space Layout Randomization) ของระบบปฏิบัติการ ซึ่งจะสุ่มฐานตำแหน่งของโปรแกรมใหม่ทุกครั้งที่ถูกโหลดขึ้นหน่วยความจำ
\end{itemize}

% ---------------------------------------------------------------------
\subsection{Step 2--3: โค้ดโปรแกรมที่ลบคำว่า \code{static} ออก}
% ---------------------------------------------------------------------

ทำการแก้ไขโค้ดโดยลบคำว่า \code{static} ออก ทำให้ตัวแปร \code{y} กลายเป็นตัวแปรอัตโนมัติ (\code{int y = 5;})

\begin{lstlisting}[style=cstyle,caption={\code{src/q1\_auto.c} ส่วนที่มีการปรับปรุง}]
    while (x > 0)
    {
        int y = 5;          /* deleted 'static' keyword */
        y++;
        printf("The value of y is %d\n", y);
        printf("The address of y is %p\n\n", &y);
        x--;
    }
\end{lstlisting}

\subsubsection{ผลการทดลอง}

ผลการคอมไพล์และรันโปรแกรม 3 ครั้ง:

\begin{lstlisting}[style=terminal,caption={ผลการทดลอง Step 2--3 (รัน 3 ครั้ง)}]

The value of y is 6      The address of y is 0x7ffde6d8b730
The value of y is 6      The address of y is 0x7ffde6d8b730

$ ./q1_auto                                # Run 3
The value of y is 6      The address of y is 0x7ffd35c62ec0
The value of y is 6      The address of y is 0x7ffd35c62ec0
The value of y is 6      The address of y is 0x7ffd35c62ec0
\end{lstlisting}

\subsubsection{การวิเคราะห์ผลและเปรียบเทียบกับ Step 1}

\begin{itemize}[leftmargin=*]
  \item \textbf{ค่าของตัวแปร ($y = 6, 6, 6$):} ตัวแปร \code{y} เป็น Automatic variable บน Stack ซึ่งมีอายุจำกัดเฉพาะในบล็อกของลูป \code{while} ในแต่ละรอบคำสั่ง \code{int y = 5;} จะทำงานเพื่อกำหนดค่าเริ่มต้นใหม่เสมอ ส่งผลให้ \code{y++} ได้ค่า $6$ เท่ากันทุกรอบ
  \item \textbf{ที่อยู่ของตัวแปรภายในการรันเดียวกัน:} เท่ากันทั้ง 3 รอบ เนื่องจากการทำงานในลูปยังคงอยู่ใน Stack Frame ของฟังก์ชัน \code{main()} คอมไพเลอร์จึงนำสล็อตหน่วยความจำเดิมบน Stack มาใช้ซ้ำ (Stack slot reuse)
  \item \textbf{ที่อยู่ของตัวแปรข้ามการรัน:} อยู่ในย่าน Stack (\code{0x7ff...}) ซึ่งต่างจากตัวแปร \code{static} ที่อยู่ในย่าน Data Segment (\code{0x5...}) โดยตำแหน่งจะถูกสุ่มใหม่ทุกครั้งตามกลไก ASLR ของ Stack
\end{itemize}

\begin{itemize}[leftmargin=*]
  \item \textbf{กรณีมี \code{static} (แตกต่าง):} ที่อยู่ของตัวแปรคงที่เป็น \code{0x404018} เท่ากันทุกครั้งที่รันใหม่ เนื่องจากแฟล็ก \code{-no-pie} สั่งให้ Linker สร้างไฟล์ Executable แบบตำแหน่งคงที่ (ELF EXEC) ซึ่งระบุ Virtual Address ที่แน่นอนตั้งแต่ขั้นตอนเชื่อมโยง เคอร์เนลจึงโหลด Data Segment ลงที่เดิมเสมอ
  \item \textbf{กรณีไม่มี \code{static} (ไม่แตกต่าง):} ที่อยู่ของตัวแปรยังคงสุ่มเปลี่ยนในย่าน \code{0x7ff...} เพราะตัวแปรอัตโนมัติอยู่บน Stack ซึ่งถูกจัดสรรและสุ่มตำแหน่งโดยตรงจากกลไก ASLR ของเคอร์เนล โดยแฟล็ก \code{-no-pie} มีผลเฉพาะการจัดวางตัวโปรแกรมและข้อมูลใน Data Segment เท่านั้น ไม่ได้ปิดการสุ่มตำแหน่งของ Stack
  \item \textbf{ค่าของตัวแปร:} คงเดิมทั้งสองกรณี เนื่องจากแฟล็ก \code{-no-pie} ควบคุมเฉพาะการจัดวางหน่วยความจำในระดับระบบปฏิบัติการ ไม่ส่งผลต่อตรรกะการประมวลผลของภาษา C
\end{itemize}

% ---------------------------------------------------------------------
\subsection{สรุปผลการทดลองข้อ 1}
% ---------------------------------------------------------------------

\begin{enumerate}[leftmargin=*]
  \item คีย์เวิร์ด \code{static} ในบล็อกทำหน้าที่เปลี่ยนอายุการใช้งานของตัวแปรให้คงอยู่ตลอดการทำงานของโปรแกรม โดยย้ายตำแหน่งจัดเก็บจาก Stack ไปยัง Data Segment ทำให้สามารถเก็บค่าสะสมข้ามการทำงานของลูปได้
  \item ตัวแปรอัตโนมัติถูกจัดสรรบน Stack และสร้างใหม่ทุกครั้งที่เข้าสู่บล็อกคำสั่ง แม้ที่อยู่ภายในการรันเดียวกันจะดูเหมือนเดิม แต่เกิดจากการใช้พื้นที่สล็อตเดิมบน Stack Frame ซ้ำ
  \item แฟล็ก \code{-no-pie} ปิดการสุ่มตำแหน่งเฉพาะส่วนของตัวโปรแกรมและ Data Segment เท่านั้น ไม่สามารถปิดการสุ่มตำแหน่งของ Stack ได้
\end{enumerate}

\subsection{หลักการพื้นฐาน: การนิยาม (Definition) และการประกาศ (Declaration)}

\subsection{Step 1: โค้ดโปรแกรมที่มี \code{extern} ทั้งสองฟังก์ชัน}

\begin{lstlisting}[style=cstyle,caption={\code{src/q2\_extern.c} โค้ดเริ่มต้นตามใบงาน}]
#include <stdio.h>
#include <stdlib.h>

int x = 20;

void display()
{
    extern int x;
    printf(" Display value of x: %d\n", x);

}

void main()
{

    printf(" Print value of x: %d\n", x);

}
\end{lstlisting}

\subsection{Step 2--3: โค้ดโปรแกรมที่ลบคำว่า \code{extern} ในฟังก์ชัน \code{main()}}
% ---------------------------------------------------------------------

ทำการแก้ไขตามข้อกำหนดโดยลบคำว่า \code{extern} ใน \code{main()} ออก (กลายเป็น \code{int x;}) ขณะที่ใน \code{display()} ยังคงมี \code{extern} ตามเดิม

\begin{lstlisting}[style=cstyle,caption={\code{src/q2\_noextern.c} ส่วนที่มีการปรับปรุง}]

{

    printf(" Print value of x: %d\n", x);

    display();
}
\end{lstlisting}

  \item \textbf{ตำแหน่งที่อยู่:} ที่อยู่ใน \code{main()} เป็นย่าน Stack (\code{0x7ff...}) ในขณะที่ที่อยู่ใน \code{display()} เป็นย่าน Data Segment (\code{0x5...} / \code{0x6...}) แสดงให้เห็นอย่างชัดเจนว่าเป็นตัวแปรคนละตัวกัน
\end{itemize}

\subsection{สรุปผลการทดลองข้อ 2}
% ---------------------------------------------------------------------

\begin{enumerate}[leftmargin=*]
  \item คำว่า \code{extern} เป็นการประกาศความจำนงเพื่ออ้างอิงตัวแปรโกลบอลที่มีการนิยามไว้แล้ว ไม่มีการจองหน่วยความจำซ้ำซ้อน
  \item การลบ \code{extern} ออกจากตัวแปรในฟังก์ชันจะทำให้เกิดการนิยามตัวแปรโลคอลตัวใหม่บน Stack และเกิดการบดบัง (Shadowing) ตัวแปรโกลบอลเดิม
  \item แฟล็ก \code{-no-pie} ทำให้ตำแหน่งของตัวแปรโกลบอลใน Data Segment มีค่าคงที่ แต่ไม่มีผลต่อตัวแปรอัตโนมัติบน Stack ที่ยังคงถูกสุ่มโดย ASLR
\end{enumerate}

\section{ข้อ 3: การจัดสรรหน่วยความจำด้วย \code{malloc}, \code{realloc} และ \code{free}}
% =====================================================================

ตามข้อกำหนดของโจทย์ การทดลองในข้อนี้ทั้งหมดจะคอมไพล์แบบปกติ (\emph{without} \code{-no-pie}) ทำให้ไบนารีทั้งหมดมีคุณสมบัติเป็น PIE ภายใต้ ASLR

\subsection{หลักการพื้นฐานของการจัดสรรหน่วยความจำ (Stack vs Heap)}

\begin{itemize}[leftmargin=*]
  \item \textbf{Stack Segment:} หน่วยความจำที่คอมไพเลอร์และระบบปฏิบัติการจัดการให้อัตโนมัติ ใช้เก็บ Local variables และ Stack frame ของฟังก์ชัน ขนาดต้องทราบแน่นอนในขณะคอมไพล์
  \item \textbf{Heap Segment:} หน่วยความจำที่โปรแกรมเมอร์สามารถขอจัดสรร (Allocate) และคืนพื้นที่ (Free) ได้เองแบบพลวัต (Dynamic) ขณะโปรแกรมกำลังทำงานผ่านฟังก์ชันระบบ
  \item \textbf{พอยน์เตอร์กับเป้าหมายที่ชี้:} ตัวแปรพอยน์เตอร์เอง (\code{\&a}) เป็นตัวแปรโลคอลที่อยู่บน Stack ขนาด 8 ไบต์ (บนระบบ 64-bit) ขณะที่ข้อมูลที่พอยน์เตอร์ชี้ไป (\code{a}) จะตั้งอยู่บน Heap
\end{itemize}

\subsubsection{การวิเคราะห์ตามแต่ละส่วนของผลลัพธ์ (Step 3)}

\begin{enumerate}[leftmargin=*]
  \item \textbf{Address of Pointer (\code{\&a}, \code{\&b}):}
    \begin{itemize}
      \item \textbf{ความหมาย:} คือตำแหน่งที่อยู่ของ \emph{ตัวแปรพอยน์เตอร์เอง}
      \item \textbf{เหตุผล:} เนื่องจาก \code{a} และ \code{b} เป็นตัวแปรโลคอล จึงได้รับการจัดสรรไว้บน Stack (\code{0x7ff...}) โดยมีระยะห่างระหว่างกันเท่ากับ \code{0x278 - 0x270 = 8} ไบต์ ซึ่งตรงกับขนาดของพอยน์เตอร์บนสถาปัตยกรรม 64-bit พอดี (แม้ \code{b} จะเป็น \code{float*} แต่พอยน์เตอร์ทุกชนิดบน 64-bit มีขนาด 8 ไบต์เท่ากัน)
    \end{itemize}

  \item \textbf{Effective Address (\code{a}, \code{b} ก่อนการจัดสรร):}
    \begin{itemize}
      \item \textbf{ความหมาย:} คือ \emph{ค่าที่ถูกเก็บอยู่ภายในตัวแปรพอยน์เตอร์} (ตำแหน่งปลายทางที่ชี้ไป)
      \item \textbf{เหตุผล:} เนื่องจากก่อนเรียก \code{malloc} ตัวแปรทั้งสองยังไม่ได้รับการกำหนดค่าเริ่มต้น จึงมีสถานะเป็น Uninitialized Pointer ซึ่งในสภาพแวดล้อมนี้ระบบแสดงผลเป็น \code{(nil)} (ค่า $0$) จากการที่หน้าหน่วยความจำใหม่ของ Stack ถูกเคอร์เนลล้างเป็นศูนย์ไว้
    \end{itemize}

  \item \textbf{After malloc Pointer a:}
    \begin{itemize}
      \item \textbf{ความหมาย:} ตำแหน่งเริ่มต้นของบล็อกหน่วยความจำบน Heap ที่ได้รับการจัดสรรขนาด 40 ไบต์ ($10 \times \code{sizeof(int)}$)
      \item \textbf{เหตุผล:} \code{a} และ \code{\&a[0]} มีค่าตรงกัน (\code{0x610cfc37b4b0}) เนื่องจากชื่ออาร์เรย์/พอยน์เตอร์ชี้ไปที่จุดเริ่มต้นของสมาชิกตัวแรก และ \code{\&a[9]} มีค่าห่างออกไป \code{0x4d4 - 0x4b0 = 0x24 = 36} ไบต์ ซึ่งตรงกับ $9 \times 4$ ไบต์ แสดงว่าข้อมูลถูกจัดวางเรียงต่อกันในหน่วยความจำ
    \end{itemize}

  \item \textbf{Array c:}
    \begin{itemize}
      \item \textbf{ความหมาย:} ตำแหน่งของอาร์เรย์ขนาด 10 สมาชิกที่จองบน Stack
      \item \textbf{เหตุผล:} \code{c} และ \code{\&c[0]} มีตำแหน่งตรงกันที่ \code{0x7ffd2a83f280} และ \code{\&c[9]} อยู่ถัดไป 36 ไบต์ที่ \code{0x7ffd2a83f2a4} แต่ตำแหน่งจัดเก็บอยู่ในย่าน Stack (\code{0x7ff...}) ซึ่งอยู่คนละส่วนกับ Heap ของ \code{a} อย่างสิ้นเชิง
    \end{itemize}

  \item \textbf{After realloc Pointer a:}
    \begin{itemize}
      \item \textbf{ความหมาย:} ตำแหน่งของหน่วยความจำหลังขยายขนาดเป็น 4000 ไบต์ ($1000 \times \code{sizeof(int)}$)
      \item \textbf{เหตุผล:} ในรอบนี้ ที่อยู่ของ \code{a} ยังคงเป็น \textbf{ที่อยู่เดิมทุกประการ} (\code{0x610cfc37b4b0}) เนื่องจากก้อนของ \code{a} อยู่ท้ายสุดของ Heap และพื้นที่ด้านหลังยังว่างอยู่ ตัวจัดสรรจึงสามารถขยายขนาดบล็อกเดิมต่อท้ายได้ทันที (In-place growth) โดยไม่ต้องย้ายที่อยู่ และ \code{\&a[999]} อยู่ห่างจาก \code{a} เท่ากับ $999 \times 4 = 3996$ ไบต์ (\code{0x610cfc37c44c - 0x610cfc37b4b0 = 0xf9c})
    \end{itemize}
\end{enumerate}

\textbf{สาเหตุที่ที่อยู่ของ \code{a} เปลี่ยนไป:}
\begin{itemize}[leftmargin=*]
  \item ใน Step 1 มีการจองเฉพาะ \code{a} ทำให้พื้นที่ถัดจากก้อนของ \code{a} ยังคงเป็นพื้นที่ว่าง ตัวจัดสรรจึงสามารถขยายขนาดในตำแหน่งเดิมได้ทันที
  \item ใน Step 4 มีการเรียก \code{malloc} ให้กับ \code{b} ก่อนการเรียก \code{realloc(a)} ทำให้ก้อนหน่วยความจำของ \code{b} ถูกจัดสรรลงไปขวางพื้นที่ต่อท้ายก้อนของ \code{a} พอดี (\code{0x...24e0} ต่อจาก \code{0x...24b0})
  \item เมื่อสั่งขยายขนาด \code{a} เป็น 4000 ไบต์ ตัวจัดสรรไม่สามารถขยายขนาดต่อท้ายที่เดิมได้เพราะติดพื้นที่ของ \code{b} จึงจำเป็นต้องค้นหาพื้นที่ว่างก้อนใหม่ที่มีขนาดใหญ่เพียงพอ ย้ายข้อมูลเดิมจากก้อนเก่าไปยังที่อยู่ใหม่ (\code{0x...2510}) แล้วจึงปลดปล่อยพื้นที่ก้อนเดิม
\end{itemize}

\subsection{สรุปผลการทดลองข้อ 3}
% ---------------------------------------------------------------------

\begin{enumerate}[leftmargin=*]
  \item ตัวแปรพอยน์เตอร์จะถูกจัดสรรบน Stack เสมอ (ขนาด 8 ไบต์บน 64-bit) ขณะที่พื้นที่หน่วยความจำที่ได้รับจาก \code{malloc} จะอยู่บน Heap Segment
  \item ฟังก์ชัน \code{realloc} จะพยายามขยายขนาดบล็อกหน่วยความจำในตำแหน่งเดิม (In-place) หากพื้นที่ด้านหลังยังคงว่างอยู่
  \item หากพื้นที่ด้านหลังถูกจัดสรรให้ตัวแปรอื่นไปแล้ว \code{realloc} จะจัดสรรบล็อกใหม่ ย้ายข้อมูลเดิม และคืนที่อยู่ใหม่ ส่งผลให้พอยน์เตอร์เดิมถูกเปลี่ยนตำแหน่ง ซึ่งโปรแกรมเมอร์ต้องอัปเดตพอยน์เตอร์และไม่ควรใช้อ้างอิงที่อยู่เดิม
  \item การใช้งาน \code{free} ต้องกระทำอย่างถูกต้องตามคู่ของ \code{malloc} เพื่อป้องกันปัญหาหน่วยความจำรั่วไหล (Memory Leak) หรือข้อผิดพลาดจากการคืนพื้นที่ที่ไม่ได้จัดสรร
\end{enumerate}
